## Purpose

The simplest binding in the editor and the template for every other one in this directory: it wraps the getter/setter pair the engine supplied into the two-method shape the [grid](../xrSdkControls/Controls/Interfaces/IProperty.cs.md) understands.

There are two of these for every value type — this one for the callable form, [a reference form](property_boolean_reference.cpp.md) for a field bound directly — and the whole family is generated by that two-by-N matrix. See [the directory README](README.md) for the shape.

## State

```text
RECORD BooleanProperty
  get : callable() -> bool          # owned copies of the engine's callables
  set : callable(bool)
```

**Invariants** — the two callables are *copied* at construction and owned by this object; they are released exactly once, whether the object is disposed deterministically or collected. The engine's original callables may go out of scope immediately after the property is created.

**Notes** — copying the callables onto the unmanaged heap, rather than storing them inline, is the incidental face of a real constraint: **a managed object may not contain an unmanaged value that needs a destructor**, because the collector will not run one. The decision that survives is that **the binding owns its accessors and outlives whatever created them**. A rebuild holds a closure and stops thinking about it.

The double release path — one deterministic, one at collection — is the same constraint from the other side: the grid may or may not dispose a cell, so both paths must free, and both must be safe to run once.

## `get`

**Contract** — calls the engine's getter and hands back the result. Called once per repaint of the row.

## `set`

**Contract** — narrows the value the cell editor produced to a boolean and calls the engine's setter. The narrowing is checked; a non-boolean is a programming error, because the cell editor was chosen from the same declaration that named the type.

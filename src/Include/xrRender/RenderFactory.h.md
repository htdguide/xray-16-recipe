**Tier floor** — T2: an abstract factory; what stops it going higher is that the objects it makes are owned across a dynamically loaded module boundary and must be freed by the module that made them.

## Purpose

Most of this directory's interfaces describe a *renderer-side companion to an engine-side object*: the engine owns a font, the renderer owns the font's texture and vertex buffers; the engine owns the weather state, the renderer owns the sky domes; the engine owns a lens flare definition, the renderer owns its shaders. The engine must be able to create those companions without naming a single concrete renderer type, and — this is the part that is easy to get wrong — must free them through the same module that allocated them.

This interface is the answer to both. One factory object, published through the global environment ([`xrAPI/xrAPI.h`](../xrAPI/xrAPI.h.md)) when a renderer is selected at startup, with a symmetric create and destroy for every companion type.

## State

`Stateless.` The factory is a singleton the renderer module owns; it holds nothing of its own.

## `IRenderFactory` — what an implementor must provide

**Contract** — for each companion type below, a `create` returning a fresh instance and a `destroy` taking one and releasing it. Creation must succeed or the engine cannot start; there is no failure channel. Neither call is thread-safe and both are made from the main thread only. An instance returned by one renderer module must be destroyed by the same module — the engine never frees one itself.

```text
FUNCTION create_<companion>() -> <Companion>
FUNCTION destroy_<companion>(instance)
```

The companions, and what each one's engine-side owner is:

| Companion | Engine-side owner | Lifetime |
|---|---|---|
| video item | a tutorial/cutscene sequence item | while the sequence is on screen |
| ui shader | any UI element, wallmark, or debug shader | while the element exists |
| stat graph render | a debug statistics plot | while the plot exists |
| object space render | the debug collision visualizer | debug builds only, whole session |
| wallmark array | a surface material's decal set | whole session, loaded with materials |
| environment render | the weather system | whole session |
| environment descriptor render | one weather keyframe | whole session, one per keyframe |
| rain render | the rain effect | whole session |
| lens flare render, flare render | the sun flare and each of its elements | whole session |
| imgui render | the debug overlay backend | whole session |
| thunderbolt render, thunderbolt descriptor render | the lightning effect and each authored bolt | whole session |
| font render | one loaded font | while the font is loaded |

**Invariants** — every companion outlives nothing and is outlived by its engine-side owner: the owner creates it in its own constructor and destroys it in its own destructor. There is no case where a companion is shared between two owners.

**Notes** — Three things here are incidental and one is not.

The declaration is generated by a macro over a type name, and half the entries are excluded from the editor build. That is C++ housekeeping; a rebuild writes the pairs out or generates them, and the editor exclusion becomes an optional capability set.

The absence of any *destroy on a renderer switch* is real, though. Renderers are selected once at startup; the engine does not support swapping one for another while running, and the companions' lifetimes assume it. A rebuild that wants a live device switch must add a "release everything the factory made" step, and there is currently nothing to enumerate.

The factory is deliberately *not* where models, lights, glows or render targets come from — those are on the renderer's own interface, because they take arguments and can fail. This factory is only for objects that are pure vessels: no arguments, no failure, one per owner. Keeping that distinction is what keeps the factory trivial to implement for a new backend.

The commented-out statistics-render entry is a removed companion whose engine side was folded into the renderer proper; nothing depends on it.

# src/xrGame/F1.h

> One shipped grenade model as its own class identifier, with all behaviour inherited and all numbers in configuration.

**Needs** — [`Grenade.h`](Grenade.h.md) · [Seam: Script binding layer](../../SYSTEM-REQUIREMENTS.md#seam-script-binding-layer)
**Used by** — nothing in this recipe; entry point or dead code.
**Tier floor** — T3: a class identity plus a script registration

## Purpose

A header-only leaf class: one of the two grenade types the games ship, distinguished from
the base grenade by nothing but its identity and its configuration section. Fuse time,
blast radius, damage curve, model and throw impulse are all read from the section by
[`Grenade.cpp`](Grenade.cpp.md) and [`Explosive.cpp`](Explosive.cpp.md).

It exists because the shipped spawn and inventory data name this class identifier, and
because script code tests for the type by name.

## State

`Stateless.`

## `CF1`

**Contract** — default construction and destruction, both empty. Every behaviour is the
base grenade's.

## Script registration

**Contract** — the class declares a script registration entry point whose bases are the
game object facade and the explosive mixin, so that a script holding this grenade sees
both the object surface and `explode`. The registration body lives with the other grenade
registrations rather than here.

**Notes** — the declaration is produced by a macro in the original. The problem the macro
solves is that every script-exported class needs an identically shaped static entry point
discovered by the registration sweep; a rebuild with reflection or a registration table
does not need the macro, only the convention that a class declares its bases for the
binding layer.

# src/xrGame/script_binder_object_wrapper.cpp

> Routes each binder lifecycle hook into the script object's method of the same name, and back out to the base implementation.

**Needs** — [`script_binder_object_wrapper.h`](script_binder_object_wrapper.h.md) · [`script_binder_object.h`](script_binder_object.h.md) · [`script_game_object.h`](script_game_object.h.md) · [Seam: Script binding layer](../../SYSTEM-REQUIREMENTS.md#seam-script-binding-layer)
**Used by** — nothing in this recipe; entry point or dead code.
**Tier floor** — T2: crossing the script boundary is a call convention, not a layout

## Purpose

A binder's hooks are declared in the engine but implemented in script. This file is the
adapter that makes that inheritance work in both directions, and it is a separate file
because it is *entirely* boilerplate generated by one rule applied eleven times.

## State

`Stateless.` It adds nothing to the binder it derives from.

## The dispatch rule

**Contract** — for every hook, two functions exist:

```text
FUNCTION hook(args)                       # the override path
  RETURN call_script_method(self, "<script name>", args)

FUNCTION hook_static(binder, args)        # the base path
  RETURN base_implementation_of(binder).hook(args)
```

The first is what the engine calls: it looks up the method by name on the script object and
invokes it, so a script that defined the method wins. The second is what the *script* calls
when it wants the inherited behaviour; it must bypass virtual dispatch or it would re-enter
the first and loop forever.

**Invariants**

- The script-side name is not always the engine-side name (`shedule_update` is `update`,
  `net_Spawn` is `net_spawn`). The mapping lives in
  [`script_binder_object_script.cpp`](script_binder_object_script.cpp.md) and both halves
  must agree.
- The hooks that return a value (`net_spawn`, `net_save_relevant`) must convert the
  script's return into the engine's boolean; a script returning nothing is a spawn veto by
  accident, which is why the default implementations return the permissive value.

**Notes**

In a rebuild where script objects can subclass engine types natively, this whole file
disappears: it exists because the host language's inheritance and the script language's
inheritance are two different mechanisms that have to be sewn together by hand, once per
method.

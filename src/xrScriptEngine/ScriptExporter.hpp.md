# src/xrScriptEngine/ScriptExporter.hpp

> The declaration a class writes to export itself to script: its registration function, and the
> classes that must be registered before it.

**Needs** — [`ScriptExporter.cpp`](ScriptExporter.cpp.md) · [`xrScriptEngine.hpp`](xrScriptEngine.hpp.md)

**Used by** — [`ScriptEngineScript.cpp`](ScriptEngineScript.cpp.md) · [`ScriptExporter.cpp`](ScriptExporter.cpp.md) · [`script_engine.cpp`](script_engine.cpp.md) · [`script_engine.hpp`](script_engine.hpp.md) · [`script_profiler.hpp`](script_profiler.hpp.md)

**Tier floor** — T2: the declaration must attach a registration to a type and make it visible to
a process-wide collector without a central list. A language with a class-level registry or a
decorator does this directly; what forbids T3 is nothing here, only the surrounding engine.

## Purpose

Declares the export node collected by [`ScriptExporter.cpp`](ScriptExporter.cpp.md), and — the
substantive half — the *declaration form* that every exporting class uses. It is the contract
between "a class that wants to be visible to script" and "the engine that builds the script
surface at startup", and it is reproduced here because it has no implementation file of its own.

## State

Stateless as a declaration; the node it declares, and the chain the nodes form, are described in
[`ScriptExporter.cpp`](ScriptExporter.cpp.md).

## The export declaration

**Contract** — A class declares that it exports itself by naming, in one place inside its own
declaration, three things:

1. that it has a registration procedure taking the VM, which the class defines itself;
2. the list of other exporting classes that must be registered first — in practice its base
   classes, and nothing else;
3. a per-class node value whose construction, before the program's entry point, enrols the class
   in the process-wide export chain.

```text
DECLARATION exports_to_script(dependencies...)
  # inside the class body, once
  register_with_script : function(vm)          # defined by the class, elsewhere
  export_node          : ExportNode {          # constructed before entry, once per class
      register     = register_with_script,
      dependencies = the export nodes of `dependencies...`
  }
```

**Invariants**

- The dependency list names *classes*, not nodes; each class is asked for its own node. A class
  that does not export itself cannot be named as a dependency, which is the right constraint:
  the binding layer only needs to know about bases it will also see.
- The dependency list is resolved lazily, when the sort asks for it, not when the node is
  constructed. This matters because construction order across modules is unspecified: a node
  constructed first may name a node that does not exist yet.
- The registration procedure is private to the class but reachable by the exporter. A rebuild
  that has no notion of privileged access can make it public; nothing depends on it being
  hidden.

**Notes** — Roughly two hundred and fifty classes carry this declaration, spread across the
game, the server-entity and the engine modules, and a handful of them declare up to three bases.
The shape a rebuild needs is: *the class body is the only place that mentions the class's script
surface, and the engine discovers the set at startup without being told.* Whether that is a
registry decorator, a compile-time reflection pass or an explicit list generated by a build step
is free — but a hand-maintained central list is not, because it makes the surface drift silently
from the classes, and criterion 10 is a statement about that surface.

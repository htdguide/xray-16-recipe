## Purpose

Three jobs. It resolves the *options* — roughly forty independent switches that together
choose which of the chapter's paths run this session, from device capabilities, user
settings and command-line overrides. It registers the handful of shader constants whose
values the engine computes rather than the material describing them. And it holds the
small delegations (model creation, wallmark submission, viewport modes) that belong to the
renderer object but carry no algorithm.

The option record is the important part. Every `IF options.x` in this chapter traces back
to a decision made here, and a rebuild that keeps the passes but invents its own option
set will find the passes no longer compose.

## State

```text
RECORD Options
  # --- G-buffer shape ---
  mrt                : bool   # device can bind three colour targets at once — required
  mrt_mixed_depth    : bool   # ...with differing bit depths, which frees the albedo path
  fp16_filter        : bool   # 16-bit float targets can be filtered when sampled
  fp16_blend         : bool   # ...and blended into
  albedo_workaround  : bool   # albedo must be staged through the accumulator, see below
  gbuffer_packed     : bool   # drop the normal target, pack the normal into position

  # --- shadows ---
  atlas_side         : int    # 1024 .. 8192, one square
  rain_atlas_side    : int
  hw_depth_compare   : bool   # device can sample a depth texture with a compare
  hw_depth_pcf       : bool   # ...and filter the comparison result
  hw_depth_format    : format
  depth16            : bool
  translucent_shadows: bool   # shadow casters may carry a colour mask
  no_shadows         : bool
  legacy_cascades    : bool   # which of the two sun implementations runs
  static_sun         : bool   # the sun is baked into lightmaps; skip it entirely
  sun_filter         : bool   # extra filtered-sun resolve pass
  shadow_jitter      : bool
  minmax_shadow      : off | on | auto | autodetect
  minmax_screen_area_threshold : int

  # --- multisampling ---
  msaa               : bool
  msaa_samples       : int
  msaa_optimized     : bool   # device can run a program per-sample on demand
  msaa_hybrid        : bool   # per-pixel main path, per-sample alpha test only
  msaa_alphatest     : none | coverage | native | native_coverage

  # --- post ---
  advanced_post      : bool   # gates depth of field, ambient occlusion, volumetrics
  volumetric_fog     : bool
  motion_blur        : bool
  distortion, distortion_enabled : bool
  ssao_blur, ssao_optimized_data, ssao_half_res,
  ssao_horizon, ssao_high_definition, ssao_ultra, ssao_vectorized : bool

  # --- misc ---
  force_gloss        : bool ; force_gloss_value : real
  tessellation       : bool
  rt_arrays          : bool   # cascades can share one array texture instead of one each
  parallel_calculate, parallel_render : bool
  fixed_function, null_target, stencil_recompress, depth_bounds : bool  # all dead, see notes
```

**Invariants** — three colour targets and a program long enough to light a pixel are
*required*; a device without them cannot run this path at all and the renderer refuses
rather than degrading. `albedo_workaround` is true exactly when the device can neither mix
depths across targets nor blend into a 16-bit float target, and it forces an extra
full-screen copy at the end of the G-buffer fill. Optimized and hybrid multisampling are
mutually exclusive. `ssao_horizon` and `ssao_high_definition` are mutually exclusive, the
latter winning.

## `create`

**Contract** — called once when the device comes up. Resolves every option, registers the
engine-computed shader constants, builds the render-target set, the model pool, the
particle library, the occlusion query pool and the frame fence. Does not touch level data.
Fails hard if the device is below the required feature level.

```text
FUNCTION create()
  # 1. hard requirements
  options.mrt = device supports >= 3 simultaneous colour targets
  options.mrt_mixed_depth = device allows those targets to differ in bit depth
  FAIL WITH "hardware below minimum feature level"
      IF NOT options.mrt OR device program length < 256 instructions

  # 2. shadow sampling
  options.hw_depth_compare = true                # every target device has it now
  options.hw_depth_pcf     = options.hw_depth_compare
  options.hw_depth_format  = vendor-preferred depth format
  options.fp16_filter = options.fp16_blend = true

  # 3. the albedo work-around, which only exists for hardware that no longer ships
  IF options.mrt_mixed_depth OR options.fp16_blend
      options.albedo_workaround = false
  ELSE
      options.albedo_workaround = true

  # 4. sizes and user settings
  options.atlas_side      = command-line override, else the user's shadow-quality setting
  options.rain_atlas_side = the user's wet-surface setting
  copy the post-processing, ambient-occlusion and multisampling settings across,
      each one ANDed with what the device and the backend actually support

  # 5. which sun runs — read from the shipped shader source, see below
  options.legacy_cascades = shipped_sun_program_is_legacy() OR user forced it

  # 6. min/max shadow maps: a per-vendor heuristic, see below
  IF options.minmax_shadow == autodetect THEN options.minmax_shadow = guess_minmax()

  # 7. engine-computed constants and subsystems
  register constant setups (below)
  targets = new RenderTargets()
  models  = new ModelPool()
  particle_library.create()
  occlusion_queries.create()
  set the normal viewport; create the frame fence
```

### `shipped_sun_program_is_legacy`

**Contract** — opens the near-cascade sun accumulation program *as data*, finds its entry
function's parameter list, and reports whether that parameter is a screen-space quad
vertex (legacy) or a light-volume vertex (cascaded). Blocks on a file read; called once.

**Notes** — this is the single most surprising decision in the chapter, and it is correct.
Three games shipped with different sun implementations, and the engine is a drop-in
replacement for all three; the installed shader source is the only artefact that states
which one the data expects. Parsing it is cheaper and more honest than a version table
that would have to be maintained against mods. A rebuild that ships its own programs may
replace this with a declaration, but must keep the *ability* to run both suns, because
both appear in the wild.

### `guess_minmax`

**Contract** — chooses whether the min/max shadow pyramid is built, from vendor and from
screen area. Pure.

```text
FUNCTION guess_minmax() -> mode
  IF vendor is A
      IF sun shadow quality is highest      THEN RETURN auto     # decide per frame
      IF light shafts are at least medium   THEN RETURN autodetect with area threshold 1600x1200
  IF vendor is B
      IF light shafts are at least medium   THEN RETURN autodetect with area threshold 1280x1024
  RETURN off
```

**Notes** — the pyramid lets the light-shaft ray march skip depth ranges that contain no
occluder. It is a win only when the marching cost dominates, which is a function of
resolution, and the two vendors' thresholds differ because their texture-fetch costs did.
This is tuning against hardware of 2009 and a rebuild may simply measure instead; the
*mechanism* (build a min/max pyramid, use it to skip) is what must survive.

## Engine-computed shader constants

**Contract** — the material system lets a pass name a constant and delegate its value to
the engine. Six such names exist on this path; each is a callback that writes four floats
into the pass's constant slot at bind time.

| Name | Value | Why the engine and not the material |
|---|---|---|
| parallax | height scale, half-height offset, and twice the reciprocal of the detail-fade distance | the fade distance is derived per frame from screen area and field of view |
| position decompression | the tangents of half the vertical and horizontal field of view, and their per-pixel steps | lets a program rebuild an eye-space ray from a pixel coordinate |
| position decompression 2 | screen width, height and their reciprocals | same reason; separated so a program can take only what it needs |
| water intensity | the current weather's water brightness, replicated | comes from the interpolated environment, not the material |
| sun-shaft intensity | the current weather's shaft brightness, replicated | same |
| alpha reference | the current alpha-test threshold | bound as state, not as data, on one backend |
| triangle level of detail | the tessellation factor | only meaningful where tessellation exists |

**Notes** — the detail-fade distance is itself derived: it scales with the screen area a
reference object covers, so that parallax and detail textures fade out at the same
*apparent* size regardless of resolution or field of view. That is why it is recomputed
every frame in [`r2_R_calculate.cpp`](r2_R_calculate.cpp.md) and read here.

## `destroy`

**Contract** — tears the above down in reverse: fence, queries, model pool, target set,
particle library, and unhooks the per-frame callback.

## `reset_begin` / `reset_end`

**Contract** — bracket a resolution or device change. Everything screen-sized is
destroyed and rebuilt; everything level-sized survives.

```text
FUNCTION reset_begin()
  sync every phase that might be running          # they hold command contexts
  let the resource manager release device objects
  FOR EACH light carried over from last frame
      abandon its occlusion queries               # the query objects die with the device
  clear the carried-over light list
  IF the detail-layer settings changed, drop the detail manager entirely
  destroy the target set, the query pool and the fence

FUNCTION reset_end()
  recreate fence, query pool and target set
  IF the detail manager was dropped, rebuild and reload it
  release every command context back to the pool
  mark "skip the next frame"        # the camera transform is not yet valid
```

**Invariants** — the skip flag is load-bearing: on the frame immediately after a reset the
device's camera state has not been refreshed, and drawing with it produces a visibly wrong
frame and a shadow-cascade fit around garbage.

**Notes** — abandoning occlusion queries is wrapped in a failure guard in the original
because a driver could fault while releasing them. The problem it solves is that query
objects have device lifetime while the light list has frame lifetime; a rebuild should
make the query handle owned by the device-lifetime object and delete the guard.

## `on_camera_updated`

**Contract** — rebuilds the view frustum from the camera's combined transform, using only
the four side planes and the far plane — the near plane is deliberately absent, because
objects straddling it must stay visible. Then, unless the main menu is up or no level is
loaded, starts the software-occluder rasterization and the detail-layer placement as
background work, both joined later in *calculate*.

## `on_frame`

**Contract** — drains the model pool's deferred-delete queue. Deletion is deferred because
a visual may still be referenced by a command context recorded earlier in the frame.

## Viewport modes — `near`, `far`, `normal`

**Contract** — set the full-screen viewport with three different depth ranges: `[0, 0.02]`
for the first-person weapon and hands, `[0.99999, 1]` for the sky, `[0, 1]` for
everything else. Cheap; no state beyond the viewport.

**Notes** — this is how the game avoids a separate depth buffer for the weapon model. By
compressing the weapon into the nearest two percent of the depth range and the sky into
the last hundred-thousandth, both are ordered correctly against the world without ever
being clipped by it. The consequence a rebuild must accept is that depth *precision* for
the weapon is two percent of what it would otherwise be, which is why the weapon's own
self-occlusion is handled by draw order rather than by depth.

## Material element selection

**Contract** — given a visual and the squared distance from the camera, return which
element of the visual's material to draw. During a shadow pass, always the shadow element.
Otherwise: the detailed element if the visual's bounding sphere reaches within the detail
distance, the coarse element beyond it. A visual with no material returns nothing, which
the caller treats as "skip".

```text
FUNCTION select_element(visual, distance_squared, phase) -> element
  IF phase is shadow THEN RETURN SHADOW
  near_edge = sqrt(distance_squared) - visual.bounding_sphere.radius
  RETURN (near_edge < detail_distance) ? NORMAL_HQ : NORMAL_LQ
```

**Notes** — subtracting the radius rather than comparing centres means a large object
keeps its detailed material as soon as its *nearest* point is close, which is what stops a
building's wall popping as you approach it.

## `dump_statistics`

**Contract** — appends the frame's light and shadow counters to the debug overlay, then
resets them. Reports totals, how many lights were visible, shadowed and unshadowed, how
many atlas batches were used, how many lights shared a batch, how many shadow walks found
nothing, and the instance-culling ratio.

## Dead options

**Notes** — several options are permanently false and their paths are unreachable:
fixed-function rendering, null render targets, the stencil-recompression trick (a
full-screen pass that used to let one generation of hardware reclaim its hierarchical
stencil after a light), and depth-bounds testing. They are kept in the source because the
pass code still branches on them. A rebuild should delete the option and the branch
together; the recipe records them so that a reader comparing against the original is not
puzzled by the missing code.

One more is a deliberate emulation switch that forces the renderer down the weakest path —
no mixed-depth targets, no hardware depth compare, no float filtering or blending — so
that the `albedo_workaround` path can be exercised on modern hardware. That is a testing
affordance worth keeping.

## Purpose

Two things live here. The first is the declaration of the renderer itself — one object,
one global instance, implementing the engine-facing renderer interface from chapter 4 and
carrying everything a loaded level's rendering needs. Its behaviour is described in
[`r2.cpp`](r2.cpp.md), [`r2_loader.cpp`](r2_loader.cpp.md),
[`r2_R_calculate.cpp`](r2_R_calculate.cpp.md), [`r2_R_render.cpp`](r2_R_render.cpp.md)
and [`r2_R_lights.cpp`](r2_R_lights.cpp.md); this page does not repeat it.

The second is the *phase runner*, which has no separate implementation file and so is
described in full below. It is the reason this renderer can overlap visibility work with
drawing at all.

## State

The renderer's own data, grouped by what owns its lifetime.

```text
RECORD Renderer
  # --- options, resolved once at device creation, never per frame ---
  options            : Options            # see r2.cpp
  stats              : FrameStats         # see below

  # --- visibility ---
  last_sector_id     : optional<int>      # the sector the camera is in
  largest_sector_id  : optional<int>      # stand-in for "outdoors"; see r2_loader
  portal_model       : CollisionModel     # portal polygons, for point-in-sector queries
  hierarchical_occluders : Occluder       # software depth occlusion, chapter 18
  hardware_queries   : OcclusionQueryPool

  # --- level-owned geometry, dropped on unload ---
  slide_windows      : list<SlideWindow>  # progressive-mesh index ranges
  shaders            : list<Shader>       # the level's material table, by index
  vertex_decls, vertex_buffers, index_buffers  : list          # normal set
  alt_vertex_decls, alt_vertex_buffers, alt_index_buffers : list  # "fast geometry" set
  visuals            : list<Visual>
  particle_library   : ParticleLibrary

  # --- subsystems ---
  details            : DetailManager      # grass and debris
  models             : ModelPool
  wallmarks          : WallmarkEngine
  targets            : RenderTargets       # the render-target set, chapter 20/21

  # --- lighting ---
  lights             : LightDatabase
  light_transforms   : LightTransformSolver
  lights_last_frame  : list<Light>        # holds occlusion queries open across the frame
  atlas              : Allocator
  package_normal     : LightPackage       # lights whose occlusion answer is in
  package_pending    : LightPackage       # lights still waiting on a query

  coarse_structure   : list<box>          # receivers recorded by the main walk, for the
                                          # legacy sun's focus refit only
  sync_point         : GpuFence
  first_frame_after_reset : bool

  # --- phases ---
  main, rain, sun, sun_legacy : Phase
```

**Invariants** — `shaders` is indexed by the number stored in level geometry, so its
order is frozen by the level file. The alternate ("fast") geometry set is optional and
only present when the level shipped it; a draw that asks for it when it is absent is a
fault, so a flag records its presence. `lights_last_frame` must be drained before the
device is reset, because it holds device query objects.

```text
RECORD FrameStats
  lights_total, lights_visible, lights_shadowed, lights_unshadowed : int
  shadow_batches_used   : int    # how many times the atlas was filled and drained
  shadow_lights_merged  : int    # lights that actually shared an atlas
  shadow_lights_clipped : int    # lights whose shadow walk found nothing to draw
  instances_visible, instances_culled : int
```

## `Phase` — the phase runner

**Contract** — a phase is one unit of off-frame work: build a visibility set, optionally
draw it, then hand its results to the frame. It exposes four steps that an implementor
fills — *initialise* (decide whether this phase runs at all this frame and how much
parallelism it may use), *calculate* (walk the scene graph), *render* (issue draws into
its own command context), *flush* (merge into the immediate context) — and two the runner
provides: *run*, called during frame preparation, and *sync*, called at the exact point in
the frame graph where the phase's output is first read.

**Invariants** — `sync` must be called for every phase that `run` started, on every path,
including device reset; a phase's active flag is cleared by `sync` so a phase runs at most
once per frame. Drawing may only be moved off the immediate context when the backend
supports parallel command recording; when it does not, *render* happens inside *sync* on
the calling thread.

```text
FUNCTION Phase.run()
  IF NOT active THEN RETURN
  main_task = SPAWN
      calculate()
      IF draw_in_parallel
          draw_task = SPAWN AS CHILD OF main_task: render()
  IF calculate_in_parallel THEN queue main_task ELSE run main_task inline

FUNCTION Phase.sync()
  IF main_task EXISTS THEN AWAIT main_task
  IF draw_in_parallel
      # the draw was a child, so awaiting the parent already awaited it
      assert draw_task finished
  ELSE
      render()            # on the caller's thread, into the immediate context
  flush()
  active = false
```

**Notes** — the draw task is deliberately a *child* of the calculate task rather than a
sibling: it must not start before the visibility set it draws exists, and making it a
child means one wait covers both. The phase does not own its command context; it borrows
one from a fixed pool for the duration and releases it in *flush*, which is what bounds
how many phases can be in flight.

Three concrete phases exist — the main view, the sun, the rain shadow — plus the legacy
sun, which is the same interface with its calculate step empty because its work cannot be
separated from its drawing. Each is described in its own twin:
[`r2_R_calculate.cpp`](r2_R_calculate.cpp.md) (main),
[`render_phase_sun.cpp`](render_phase_sun.cpp.md),
[`render_phase_sun_old.cpp`](render_phase_sun_old.cpp.md),
[`r3_R_rain.cpp`](r3_R_rain.cpp.md).

## `Renderer` — exported surface

Described elsewhere; listed here because the headings are the public surface.

- **Lifecycle** — `create`, `destroy`, `reset_begin`, `reset_end`, `level_load`,
  `level_unload`. See [`r2.cpp`](r2.cpp.md) and [`r2_loader.cpp`](r2_loader.cpp.md).
- **Frame** — `on_camera_updated` (rebuild the view frustum, start software occlusion and
  detail-layer work), `calculate`, `render`, `render_menu`, `render_forward`,
  `on_frame`, `before_world_render` / `after_world_render` (both empty hooks kept for
  game-side extensions), `screenshot`.
- **Lighting** — `light_create`, `glow_create` (glows are inert on this path: the object
  exists and accepts every setter, because the game layer creates them unconditionally,
  but nothing renders), `render_lights`, `render_indirect`.
- **Models** — create, duplicate, delete, prefetch and clear, all delegating to the model
  pool; plus particle-effect and detail-model creation.
- **Wallmarks** — add static (projected onto a collision triangle) or skeletal (projected
  onto an animated mesh), and clear.
- **Occlusion** — `occ_visible` for a visibility record, a box or a polygon, each asking
  the software occluder; and the hardware query begin/end/get triple.
- **Material selection** — given a visual and its squared distance, choose which pass
  element to draw: during a shadow pass always the shadow element, otherwise the detailed
  element inside a distance threshold and the coarse one beyond it.
- **Viewport modes** — near, far and normal, which compress the depth range so the
  heads-up display and the sky can never intersect world geometry.
- **Backend identity** — generation, backend name, feature level, and the directory the
  shipped shader sources are read from, which differs per backend because the two
  backends ship different dialects of the same programs.
- **Shader options** — a list of name/value pairs prepended to every program compiled
  this session, so that capability decisions (multisampling mode, ambient-occlusion
  variant) reach the program source that ships as data.
